# Local macOS later-stage performance test build

This local Apple Silicon candidate includes the rc1 optimizations and two
additional changes. It is not a published release. The AVAC runtime uses a
separate `1.0.1-rc2` cache; the bundled WAVE runtime remains `1.0.0`.

## Why Trift slows down

The live rc1 run showed both shorter physical time steps and more computation
per step. During simulated seconds 0–5 it averaged 0.0532 s per time step and
0.388 s of wall time per step. During seconds 30–34 these became approximately
0.0237 s and 0.868 s, respectively. The number of wet cells increased from
about 140,000 initially to 526,000 at 32 s.

At 32 s, the largest estimated directional signal speed, `|u| + sqrt(g*h)`,
was about 41.5 m/s in a cell with 2.72 m of snow. With the 2 m grid and CFL
target 0.5 this predicts a time step near 0.0241 s, consistent with the run.
Thus the CFL restriction is not caused by an extremely thin high-speed film.

## Changes

- Moving wet/wet Riemann interfaces bypass static-yield calculations that
  cannot satisfy the existing exact-rest requirement. The guard uses the
  same computed speeds as the original final test, with no new threshold.
  Dynamic waves, stopping behavior, and static-yield conditions are unchanged.
- A level with no coarse/fine flux registers uses ordinary dynamic OpenMP
  scheduling. Merely skipping the ordered write was insufficient: an ordered
  loop also delays retirement of iterations that never enter that write.
  Levels with shared coarse/fine registers retain ordered flux commits.
  The choice uses actual registers, not an assumption about the finest level.

Equations, mesh resolution, numerical precision, CFL limits, output times,
and peak-check frequency are unchanged.

## Later-state timing and equivalence check

The 30 s Trift solution frame was read without modifying the live run. Its
three conservative state components were supplied through the existing
`qinit_type=5` binary reader on the same aligned 2 m mesh. Both binaries then
advanced from 30 to 31 s with eight threads and the same 44 accepted steps.
This reinitializes observations at 30 s; it is not a checkpoint continuation
of the full historical peak fields.

| Binary | Level advancement | Through final scheduled output | Complete process |
| --- | ---: | ---: | ---: |
| rc1 | 51.03 s | 70.96 s | 106.64 s |
| rc2 | 43.13 s | 63.51 s | 101.14 s |

The first two columns come from `timing.csv`; complete process time also
includes input loading and final peak-file writing. These are single-run
measurements made while the original simulation continued running. Background
CPU contention affects the numbers; they are not clean standalone throughput
estimates or predictions of the full avalanche's completion time.

The initial/final solution binaries, both FGout frames, and FGmax file were
byte-identical. The logged CFL/time-step sequences were identical too.
Compiled tests cover exact Riemann equivalence, avoiding unnecessary friction
calls, scheduler progress, and ordered commits for mixed/full flux-register
sets. The native two-level CFL-retry test also passed with identical outputs
for one/four threads and rejected-trial/direct accepted-time-step runs.
The final numerical/packaging suite passed 705 tests; its one opt-in native
test was run separately and passed. The staged macOS plugin passed 22
runtime-dependent checks and release integrity validation. Its installed
solver hash matches the binary used for the final later-state benchmark.

## Local packaging and testing

The package builder now accepts `--plugin-version 1.0.1-rc2 --experimental`.
These flags change only staged metadata and the local artifact. Source
metadata and the existing Windows release descriptors remain at `1.0.0`.

Install `avac_qgis-1.0.1-rc2-macos-arm64.zip` from QGIS's **Install from ZIP**
after finishing or stopping the current run, restart QGIS, and prepare a new
AVAC run. Keep the physical and numerical settings unchanged for comparison.
The running solver is not replaced or interrupted by building this candidate.
