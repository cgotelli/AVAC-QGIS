# Local macOS WAVE performance test build

This unpublished Apple Silicon candidate includes the AVAC rc2 improvements
and the WAVE fixes below. Both bundled runtimes use separate `1.0.1-rc3`
caches, so WAVE cannot silently reuse the installed `1.0.0` executable.
Published source metadata and Windows release descriptors remain at `1.0.0`.
Nothing has been pushed.

## Causes and changes

The Trift WAVE case prepared on September 6 has 20,989,449 cells at 1 m
resolution and 10,880 patches under the old default. Its installed WAVE
runtime did not contain the recent AVAC/shared performance improvements.

- WAVE overrides the shared FGout module. Its old interpolation loop scanned
  the entire output grid for every patch: about 228 billion candidate checks
  per pass in this case. Profiling confirmed both this work and workers
  waiting for the fixed-grid lock. The new bounds visit only candidate
  centers near each patch, retaining the original ownership predicate,
  interpolation, and traversal order.
- FGout's early/late buffers allocated 10 components although this model
  needs six. Equation-count-based allocation saves about 1.25 GiB here,
  without dropping any field or reducing precision.
- Single-level WAVE runs now use a patch limit of 250 instead of 60. This
  case has 512 patches, with ghost-cell overhead reduced from about 19% to
  4%. The physical cell size and domain do not change. Multilevel AMR retains
  the existing limit of 60. Short benchmarks did not establish a separate
  total-time gain from patch enlargement after the other fixes; it reduces
  boundary work and storage overhead.
- Patches outside the shoreline-source bounding box skip inflow searches.
  Time lookup uses a stateless binary search. Source order, midpoint
  interpolation, half-open ownership, and conservative V2 area scaling are
  unchanged, including under AMR and concurrent workers.
- Exactly stationary wet cells skip redundant Manning calculations after
  inflow and dry cleanup. Moving cells and subsequent forcing still receive
  their normal updates.
- The rebuilt WAVE runtime includes the shared empty-patch flux shortcut
  and flux-register-aware parallel scheduling. Its standard-water CFL probe
  now also skips exactly empty patches, including all state components and
  ghost cells. No dry-tolerance shortcut or velocity cap was introduced.

The bounded FGout implementation also now handles zero-spacing singleton
axes safely in both the WAVE and shared modules. AVAC was rebuilt to include
this edge-case correction and keep the runtime consistent with source.

## Native checks on the full Trift grid

The original case was read without modifying its configuration or outputs.
Temporary runs used eight threads, the same 1 m mesh, and shortened output
schedules. The following paired measurements use identical 250-cell patch
limits to isolate runtime changes from partition changes.

| Short test | Original advancement | New advancement | Original complete process | New complete process |
| --- | ---: | ---: | ---: | ---: |
| Initial lake, 0–0.001 s | 16.00 s | 1.26 s | 30.65 s | 13.33 s |
| Active inflow, 10–10.05 s | 33.80 s | 3.11 s | 50.62 s | 17.35 s |

Advancement is the level wall time in `timing.csv`; complete process time
also includes initialization and writing all scheduled outputs. The active
test starts from the initial lake state at time 10 with the original source
series; it is not a restart of an evolved 10-second solution. It takes five
accepted steps and produces nonzero momentum. These are single-run timings,
with some concurrent build/test activity, not a full 150-second validation
or a guaranteed end-to-end speedup.

In both paired checks, initial/final solution binaries, auxiliary binaries,
FGout binaries, and logged CFL/time-step sequences were identical. The final
packaged WAVE binary was used for the active check. Comparing the new runtime
with patch limits 60 and 250 also gave identical FGout binaries and CFL
sequences. Small differences in printed total-mass summation result from
the changed partition/reduction order.

A separate native WAVE check exercised two-level AMR, internal inflow,
Manning friction, and boundary-induced CFL rejection on both levels. The
original binary and the new binary with one/four threads gave identical
solution and fixed-grid comparison frames and CFL sequences. AVAC's native
transactional CFL-retry test also passed.

Compiled regression tests compare the optimized and original kernels for
grid intersections, singleton axes, buffer indices, dry patches, source
edges, source accumulation, time intervals, AMR areas, and later forcing.
The full validation suite passed 895 tests with one opt-in native test
skipped; that native test was run separately and passed. The source plugin
checks passed 100 tests; 22 runtime-dependent checks passed against the
staged macOS plugin. Release validation and production-installer checks
confirmed both independent runtime caches, binary hashes, and current
`setrun.py` writers. The stale AVAC source acceptance pin was updated for
the already-tested rc2 exact-rest optimization; no AVAC physics changed here.

## Remaining costs and local testing

The 1 m grid still imposes short physical time steps: around 0.0147 s in
the short active-inflow check with CFL target 0.5. Equations, stability
limits, resolution, precision, and the normal output schedule are unchanged.

Storage is a separate constraint. At the present 151-frame settings, the
standard solution, auxiliary, and FGout binaries total approximately
217 GiB before postprocessing and other files. This exceeds the free space
observed during testing. Use an output volume with sufficient free space,
or explicitly choose fewer saved frames. This build does not silently
remove output products or reduce their precision.

Install `dist/macos-arm64-1.0.1-rc3/avac_qgis-1.0.1-rc3-macos-arm64.zip`
through QGIS's **Install from ZIP**, restart QGIS, and prepare a new WAVE
run from the existing completed AVAC result. A previously prepared run
retains its old patch settings and may retain its old runtime selection.
There is no need to rerun AVAC to test these WAVE changes.
