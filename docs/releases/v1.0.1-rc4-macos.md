# Local macOS WAVE grid-fitting test build

This unpublished candidate fixes WAVE preparation for DEM/domain dimensions
that are not divisible by the chosen mesh spacing. It retains the rc3 solver
performance improvements. The plugin is `1.0.1-rc4`, with the unchanged AVAC
`1.0.1-rc3` runtime and a separate WAVE `1.0.1-rc4` runtime/cache containing
the corrected data writer. Published Windows descriptors remain unchanged.

Both the QGIS interface and WAVE preparation previously rejected a
nondivisible AVAC rectangle. They now use one metadata-only fitting helper
that reuses AVAC's existing edge-trimming implementation:

- Remove the minimum number of native DEM rows and columns.
- Split removal evenly between opposite sides; remove an odd extra row or
  column from the north/east edge.
- Keep the requested mesh spacing and native DEM alignment. Do not stretch
  the extent, modify the original DEM, or change the completed AVAC run.
- Use the retained rectangle consistently for the water preview, terrain
  halo, force-dry mask, shoreline sources, gauges, solver, and fixed-grid
  output. QGIS reports the retained dimensions and bounds.

The computational spacing must still be a whole-number multiple of the
native DEM spacing, and at least two WAVE cells must remain on each axis.
An out-of-domain gauge or invalid/misaligned source extent still raises an
explicit error. Existing WAVE block-averaging and topography-only halo rules
are unchanged; the fitting step itself only removes edge cells.

WAVE's data writer also no longer truncates `span / cell_size` to an integer.
It validates and rounds whole-cell counts once, then shares them between
the solver and FGout. This prevents a row/column from being lost solely to
floating-point roundoff at fractional spacing or large projected coordinates.

Checks passed: 178 source plugin tests, 931 validation tests (one opt-in native
test skipped), eight focused GUI-method checks included in the plugin suite,
and 73 selected checks against the staged macOS package. The GUI-method
checks execute the production methods with lightweight QGIS surface stubs.
A native packaged preparation/run test trimmed a 43 × 45 cell, 1 m DEM to
a 10 × 11 computational grid at 4 m, with bounds X [1, 41], Y [0, 44]. The
generated solver and FGout grids matched exactly; all three output frames
were finite and the solver reached the configured final time. This small
test used synthetic inflow to isolate grid preparation from AVAC history
generation; it is not a new physical validation benchmark.

Release validation and temporary production-installer checks verified the
packaged GUI/core files, backend writer, binary hashes, and distinct runtime
caches. All user run directories were left untouched. Nothing was pushed.

Install `dist/macos-arm64-1.0.1-rc4/avac_qgis-1.0.1-rc4-macos-arm64.zip`,
restart QGIS, and prepare a **new WAVE run** from the completed AVAC result.
Existing prepared runs retain their original grid files; AVAC need not be
rerun. The previously noted storage requirements are unchanged.
