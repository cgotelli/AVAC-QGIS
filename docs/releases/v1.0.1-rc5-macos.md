# Local macOS WAVE CFL-performance test build

This unpublished Apple Silicon candidate retains rc4's grid-fitting fix
and adds only the two approved WAVE CFL-preflight optimizations. The plugin
and WAVE runtime use `1.0.1-rc5`; the bundled AVAC runtime remains the tested
`1.0.1-rc3` archive. Source release metadata and Windows descriptors remain
unchanged. Nothing has been pushed.

## Changes and safety boundaries

- Reuse one pair of private CFL scratch buffers per OpenMP worker. Storage
  grows only when necessary and is remapped to the current patch's exact
  dimensions. This avoids incorrect strides when AMR changes patch shape
  and avoids compiler-generated copy temporaries. Every trial still copies
  all active and ghost-cell state from the accepted solution. The auxiliary
  dummy for zero auxiliary fields is reinitialized.
- Use an exact speed-only normal Riemann callback for WAVE's CFL preflight.
  It retains the original depth cleanup, dry-wall and overtopping decisions,
  Roe/Einfeldt expressions, `riemanntype` refinements, wall masks, and mapped
  coordinate scaling. The wave decomposition that does not affect speeds is
  omitted. Accepted time steps still use the full upstream augmented solver.

The shared advance driver selects these changes only with
`WAVE_CFL_FAST_PATH`. The macOS build log confirms the flag was used; build
tests also verify the Windows source/module lists and AVAC's unchanged
dispatch. Both native solvers were force-rebuilt sequentially to test their
distinct shared-object compilation contexts. Command-line overrides of
`FFLAGS` must retain the WAVE define to enable this optional fast path.

There is no CFL relaxation, altered physical equation, precision reduction,
new wet/dry exclusion rule, change to source integration, or output-policy
change. Private `b4step2` preparation and whole-level CFL retries are retained.
Scratch memory remains allocated per worker until process exit; it is bounded
by the largest state and auxiliary patch each worker has processed.

## Verification

- 1,016 validation regression tests passed; the one opt-in native AVAC test
  was then enabled separately and all six CFL-retry tests passed.
- 178 source-plugin tests passed, excluding the separate process-launcher
  test module. These checks used the valid macOS runtime descriptors from
  the previous staged package without changing the source Windows records.
- 73 checks passed against the staged rc5 plugin. Its production runtime
  installer verified both cache versions, binary provenance, and current
  data writers. A packaged native WAVE run also repeated the nondivisible
  DEM grid-fitting check and reached its final time with finite outputs.
- 72 compiled speed tests compare the real upstream Riemann solver, the
  new callback, the patch CFL preflight, and the accepted-step CFL. They
  cover exact thresholds, wet/dry walls and overtopping, moving water,
  random states, pressure, mapped coordinates, ghost cells, 3/5 equations,
  and extreme/nonfinite inputs. Finite-state comparisons are bitwise and
  run with invalid/division-by-zero/overflow traps. IEEE-edge tests preserve
  the reference NaN classifications and CFL decisions without traps.
- 13 buffer/build tests cover growth, alternating wide/tall patches,
  changing field counts, 1/4 workers, changing team sizes, repeated and
  backward-time trials, and aggressive scratch mutations. Runtime bounds
  checks and array-temporary errors are enabled. Accepted state is unchanged.
- A native WAVE test with two AMR levels, internal inflow, Manning friction,
  and boundary-induced CFL rejection compares rc4 with rc5 using one and
  four workers. All solution and FGout frames and logged CFL/retry sequences
  are byte-identical. Rejection occurs on both levels.

The IEEE tests also expose an existing upstream limitation: some invalid or
extreme states can produce invalid fluxes while reporting finite CFL. This
optimization preserves the tested behavior; it does not repair that separate
diagnostic issue or make such states physically valid.

## Performance scope

Callback-only microbenchmarks on this Mac measured approximately 2.4–3.1
times faster speed calculation, depending on the state. This is not an
end-to-end solver speedup: the accepted solve, state copies, boundary work,
and output remain necessary.

The full-grid comparison uses a temporary copy of the Trift WAVE case
`wave_20260906_133341`, retaining its 1 m grid (5,787 by 3,627 cells),
250-cell patch limit, eight workers, and CFL target 0.9. It starts the
initial lake at time 10 with the original nonzero inflow series and advances
to 10.5 in 20 accepted steps. This is a bounded performance/regression probe,
not a restart of an evolved 10-second solution or a new physical validation.
All numerical solution/auxiliary/FGout files and CFL sequences match rc4.
The level wall-time column in `timing.csv` excludes the CFL preflight and
must not be used alone to measure these changes.

Three paired complete-process measurements were rc4 23.49/20.91/21.90 s
and rc5 22.17/20.54/20.13 s. The median decreased from 21.90 to 20.54 s
(about 6.2% less elapsed time), including initialization and output. Timing
varies and the first reference run overlapped a build; these short tests
do not establish a guaranteed full-simulation speedup. All six runs produced
identical numerical files and CFL sequences. Temporary test drivers,
configuration copies, logs, timings, and output hashes were retained under
`/private/tmp/wave-cfl-performance.t5iL4I`; the large generated benchmark
binaries were removed after comparison to recover disk space.

## Testing in QGIS

Install `dist/macos-arm64-1.0.1-rc5/avac_qgis-1.0.1-rc5-macos-arm64.zip`
using **Install from ZIP**, restart QGIS, and prepare a new WAVE run from
the existing completed AVAC result. AVAC does not need to be rerun. The
separate rc5 WAVE cache prevents reuse of the old executable.

The Trift input files and user results were not modified. The existing
full-run storage requirement remains substantial; the output schedule and
precision have not been reduced by this build.
